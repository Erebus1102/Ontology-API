# Runtime 2.0 基座 Implementation Plan — V3.0 本体手术 + Key 模型 + v1 契约对齐

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 为 lineage（迭代 1）/ submissions（迭代 2）铺好共同基座——补 V3.0 缺失的 3 个类与 SHACL、删冗余决策类、扩展 Key 模型并接通 tenant→图作用域、把 resolve/render 收敛到 v1 目标形态。本轮**不交付** lineage / submissions 端点。

**Architecture:** 三工作流。**A（Layer 3 本体手术）** 与 **C（auth 层 Key 模型）** 无文件交集，可并行；**B（API 契约收敛）** 依赖 C（Key 推导作用域），在 C 之后执行。A 的破坏性 Release 与 B 的契约切换分属不同 commit。本体派生制品（ttl / protege view）由 jsonld 经 `make generate` 自动产出，同构守卫据此自动通过。

**Tech Stack:** rdflib Dataset + `.trig` 命名图（零新增依赖）；FastAPI + pydantic；pyshacl（`inference="rdfs"`, `advanced=True`）；owl:Class / sh:NodeShape / sh:sparql；pydantic Principal；JSON OpenAPI 3.1。

## Spec Reconciliations（探查代码库后对 spec `docs/mvp/04` 的精确化）

落地时以本节为准。本节含两类核对：**vs 代码库**（#1/#2/#5/#6）与 **vs 权威文档 `docs/mvp/01-03`**（#3/#4/#7/#8）——后者会**反向修改上游文档**，统一在 Phase 0 文档基线 commit 落地（设计基线先于手术代码固定）：

1. **类数基线 = 102**（spec 写的 104 是误把 2 个匿名 `owl:Class` enum 闭包数进去）。本轮落地后类数 = 102 − 3 删（StrategicChoice/StrategicDecision/OperatingDecision）+ 3 增（Agreement/FeedbackRecord/Product）= **102 命名类**（不新增 AgreementStatus enum 类，见 Reconciliation 5）。
2. **spec §A.2「TRAVERSAL 移除 selectedAs/decidedAs」是 no-op**：`query_plan.py` 现就**不含**这两个谓词（它们只存在于 OWL schema 三件套）。真正要做的是**加入 5 个新对象属性 + bump 版本号**。
3. **`Agreement ⊂ AttributedAssertion`**（spec §A.1 + 上游 `docs/mvp/02` 为准；非权威的 `docs/architecture/2026-08-13…` 说 ⊂ Decision，不采信）。后果：现有 `StrategicDecision` 实例迁移为 Agreement 后，会被 `AttributedAssertionShape` 深类靶向，必须补 `assertedBy` + `recordedAt`（值取自同源 DRI 的姊妹 provenance 断言，非杜撰）、并以新 `agreementStatus` 取代 `hasStatus`（DecisionStatus 不再适用）。属受控 diff，逐条对应实例迁移映射（A4 落盘为 `migration-map.md` 制品，逐字段记取值出处）。**附加（Flag #1）**：迁移实例带 `reviewCondition`（line 42），其 `rdfs:domain` 现为 `Decision`——pyshacl `inference="rdfs"` 会把迁移后的 Agreement 反推为 `Decision`，污染验证图类型。A1 一并放宽 `reviewCondition` 的 domain 为 `owl:unionOf(Decision, Agreement)`（复审条件对共识同样成立，零信息丢失）。
4. **`adoptsJudgement` 本轮不强制**：spec §A.1 理想要求 Agreement 必有 adoptsJudgement，但数据中**零 Judgement 实例**，强制会逼出杜撰（违反 CLAUDE.md「禁止为填满 Shape 补造实例」）。本轮 `AgreementShape.adoptsJudgement` 取 `sh:minCount 0`；submissions 迭代引入真实 Judgement→Agreement 边后再收紧到 1。此偏差在 §6.1 验收单与 A.2 任务中显式记录。
5. **`agreementStatus` 按字面 spec 建为 xsd:string 数据属性**（值 `"close"|"go_on"`，SHACL `sh:in` 约束）。与本体现在用「对象属性→status 个体」的 `hasStatus` 模式不一致——本轮沿用 spec 字面定义，不一致点记录为后续统一项。
6. **跨实体"同 Issue 最多一个有效 Agreement"用 `sh:sparql`**（与 shapes 文件既有风格一致），不引入 `sh:qualifiedValueShape`。
7. **scenario id 以权威注册表为准（vs 文档反向核对，P0-1）**：`scenarios.py` 四场景 id **照抄** `docs/mvp/01 §5` + `docs/mvp/03 §2` 权威表——`meeting_supervision` / `strategic_research` / `expert_panel`（→ decision_preparation）与 `task_followup`（→ **mission_review**）。`task_followup` 裁定映射既有 `mission_review`（图集合 = confirmed+provenance+derived，正是任务跟进所需），**不为一个名字新增 purpose 枚举**（无收益的面扩张）；docs/mvp/03 §2 line 58 那格由 `execution_support` 改为 `mission_review`（Phase 0）。注册表存在的意义就是不允许第二套 id。
8. **`DecisionRecordShape.recordsDecision`（minCount 1, sh:class Decision）与 V3.0 语义冲突（审计发现，记录不阻塞）**：战略会议记录的是 Judgement/Agreement 而非 Decision。当前 DecisionRecord 零实例不触发，但迭代 2 会议记录落盘时这条 Shape 会逼造 Decision 实例。A3 删除清单标记为**迭代 2 前必须放宽**，本轮不改。

```python
"""SHACL 正负向用例：V3.0 Agreement/FeedbackRecord/Product Shape。"""
from pathlib import Path
from rdflib import Graph, Dataset, Namespace
from rdflib.namespace import SH
from pyshacl import validate

ROOT = Path(__file__).resolve().parents[1]
TKOS = Namespace("https://ontology.tokenking.ai/tkos#")
SHAPES = ROOT / "ontology/shapes/tkos-validation-shapes.jsonld"
ONTOLOGY = ROOT / "ontology/schema/tkos-ontology.jsonld"
CASES = {
    "agr-positive": (True, 0),
    "agr-negative-no-status": (False, 1),
    "agr-negative-score-out-of-range": (False, 1),
    "agr-negative-feedback-no-score": (False, 1),
    "agr-negative-product-dup-id": (False, 1),
    "agr-negative-two-go-on-same-issue": (False, 2),
}

def merged(dataset: Dataset, case_name: str) -> Graph:
    g = Graph()
    for gn in (TKOS["test-baseline"], TKOS[case_name]):
        for t in dataset.graph(gn):
            g.add(t)
    return g

def main() -> None:
    shapes = Graph().parse(SHAPES, format="json-ld")
    ontology = Graph().parse(ONTOLOGY, format="json-ld")
    dataset = Dataset().parse(ROOT / "tests/v2.x-agreement-cases.trig", format="trig")
    failures = []
    for case_name, (exp_conforms, exp_count) in CASES.items():
        conforms, results_graph, _ = validate(
            data_graph=merged(dataset, case_name), shacl_graph=shapes, ont_graph=ontology,
            inference="rdfs", advanced=True)
        count = len(set(results_graph.subjects(SH.resultSeverity, None)))
        ok = conforms == exp_conforms and count == exp_count
        print(f"{case_name}: conforms={conforms}, results={count}, expected={exp_conforms}/{exp_count}")
        if not ok:
            failures.append(case_name)
    if failures:
        raise SystemExit("Unexpected SHACL outcome: " + ", ".join(failures))
    print("v2.x-agreement: all cases pass")

if __name__ == "__main__":
    main()
```

```python
    def allowed_graphs(self, purpose: str, registered: set[str], restricted: set[str],
                       principal_scopes: set[str] | None = None) -> list[str]:
        if purpose not in self.purpose_allowed:
            raise ValueError(f"unknown purpose: {purpose!r}")
        base = [g for g in self.purpose_allowed[purpose] if g in registered and g not in restricted]
        if principal_scopes is not None:
```

# TKOS 本体 V2.0 辩护与修订说明

## 裁定

审计对 V1.2 的主要判断成立。V2.0 改为一个共享核心、经营模块、决策溯源模块、治理模块和多个运行时命名图。Persona 不再作为一套以“画像事实”为中心的独立本体发布；它成为决策溯源模块中的可追溯记录与可重算视图。

V2.0 保留了 TKOS 的经营语义主链。CompanyOutcome、DomainOutcome、MissionOutcome、Domain、Mission、DRI 承诺、Evidence、Review、Lesson 仍是业务骨架。调整发生在人员、决策、关系、时间和运行时治理的表达方式。

## 审计逐项处理

| 审计项 | 裁定 | V2.0 处理 |
|---|---|---|
| 1. 以实例变化论证双本体拆分 | 成立 | 撤回该论据。模式由共享核心统一发布；企业事实、候选判断、敏感个人记录和推导结果由 RDF Dataset 命名图隔离。独立模块的依据改为语义内聚、治理责任、复用边界和发布依赖。|
| 2. Persona 混合事实、确认判断与系统推测 | 成立 | 新增 `DecisionRecord`、`AttributedAssertion`、`DecisionLearning` 和 `DecisionProfileView`。`DecisionProfileView` 由当前有效记录生成，具有可撤销和可重算语义。|
| 3. DRI 与一号位建成固定人员类别 | 成立 | 新增 `Person`、`Role`、`RoleAssignment`、`DecisionMakerRole`、`DirectlyResponsibleRole` 和 `AuthorityBoundary`。Mission 通过唯一 `hasResponsibleAssignment` 关联责任承担；承担记录带人员、范围和有效区间。原 `DirectlyResponsibleIndividual` 与 `ownedBy` 保留为兼容项并标记废弃。|
| 4. 宽关系不能承载追溯元数据 | 成立，部分已有收敛 | V1.2 的 `supports` 已限定为 `DomainOutcome → CompanyOutcome`，Mission 层使用 `contributesTo`，因此“同一属性同时表达三种语义”的描述不适用于 V1.2 文件。V2.0 新增 `OutcomeContribution`、`EvidenceSupport`、`EvidenceChallenge`、`ConfirmationEvent`、`RevisionEvent`，用关系对象保存范围、来源、确认和时间。|
| 5. 时间与版本不足 | 成立 | 新增 `hasValidityInterval`、`recordedAt`、`confirmedAt`、`usedAt`、`RevisionEvent`、`revisionOf`、`revisedTo` 与 `revisionKind`。`validFrom`、`validUntil` 继续用于兼容，复杂时间由 OWL-Time 区间承载。|
| 6. OWL、SHACL 与业务规则边界 | 成立 | README 明确收紧职责。OWL 处理分类、逆向关系、基数和稳定语义；SHACL 处理完整性、一致性和写入门禁；应用规则处理时钟、阈值、升级、访问和人工确认。SWRL 保留已有的单调推导，真实试点后逐条复核。|
| 7. 权限延后 | 部分成立 | 原业务范围明确将权限留到后续版本，不能将完整访问控制声称为 V2.0 已实现。V2.0 加入 `AuthorityBoundary`、知识图分区、来源记录和 Context Pack 使用时间，作为试点前的最小治理模型。读取目的、敏感级别、允许主体、撤回和审计仍是首个真实试点的应用层 P0 门槛。|
| 8. 缺乏架构最优性证据 | 成立 | V2.0 不宣称最优。下一阶段以 Competency Questions、负向 SHACL 测试、时间与角色测试、敏感图访问测试和同一真实案例的三方案对照建立证据。|

## 关键语义决定

### 人员与责任

`Person` 表达人员。`RoleAssignment` 表达某人何时、在何组织或事项范围内、以何角色承担何种边界。一个 Mission 有一项当前责任承担记录，该记录的角色应为 `DirectlyResponsibleRole`。这保留了 TKOS “一项 Mission 有一位最终 DRI”的经营要求，也使人员角色随时间和事项变化可被表达。

### 决策画像

系统从以下三类记录生成决策画像视图。

1. `AttributedAssertion` 保存某人明确表达或确认的判断。
2. `DecisionRecord` 保存真实发生的决策事件及其输入、选择、确认和结果。
3. `DecisionLearning` 保存案例复盘后、经确认可复用的学习。

`DecisionProfileView` 只是一份针对当前时间、事项和用途生成的视图。它不被当作对某人恒久不变的断言。

### 证据、贡献、确认与修订

直接属性仍提供高效查询。需要表达证据支持强度、挑战关系、结果贡献范围、确认人、确认时间、修订类型和理由时，使用对应的关系对象。V2.0 将旧 `isProvenBy` 标记为兼容属性，并引入 `supportedByEvidence` 与 `EvidenceSupport`，避免把经营证据误说成形式上的绝对证明。

### 时间与版本

有效时间回答某项内容在业务世界何时适用。记录时间回答系统何时获得信息。确认时间回答何时成为可用口径。使用时间回答某次 Context Pack 在何时被编译和消费。修订事件说明新旧对象之间是替代、撤回、范围缩小还是文字修订。

## V2.0 仍待验证的边界

V2.0 通过 JSON-LD 与 rdflib 结构解析。它尚未完成带真实企业实例的 HermiT 或 Pellet 一致性证明，也没有完成带真实敏感数据的端到端权限测试。`DecisionProfileView` 的筛选、排序和自然语言编译属于 Context Resolver 与 Agent Skill 的运行时职责，不属于 OWL 推理机。

## 规范依据

- RDF Dataset 由默认图和零个或多个命名图组成，适合分离不同来源和快照。<https://www.w3.org/TR/rdf11-concepts/#section-dataset>
- PROV-O 提供 Entity、Activity、Agent、生成、归属和派生语义。<https://www.w3.org/TR/prov-o/>
- W3C ORG 以角色和成员关系表达组织承担，而非把职位固化为人员类型。<https://www.w3.org/TR/vocab-org/>
- OWL-Time 提供瞬间与区间的通用时间表达。<https://www.w3.org/TR/owl-time/>
- OWL 的开放世界语义适合知识表达与推导，完整性门禁由 SHACL 和应用规则承担。<https://www.w3.org/TR/owl2-primer/>
- ODRL 为后续 Permission、Prohibition、Duty、Party、Asset 与 Constraint 提供可复用词汇。<https://www.w3.org/TR/odrl-model/>
